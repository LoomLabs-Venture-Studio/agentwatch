# agentwatch market research, November 2026

Scope: what users want that agentwatch lacks. I checked the repo first, so items it already has are not listed as gaps: `watch-all --budget` alerts, `config-scan` flags Codex `danger-full-access` and `bypassPermissions`, guard/coach/breaker are Claude Code only, skills scan reads markdown only, there is no OTel output and no git correlation.

## 2. Community demand signals

- Spend caps: Claude Code [#95964](https://github.com/anthropics/claude-code/issues/95964) points out that `--max-budget-usd` works only in print mode, and it cites stuck loops. Also [#74709](https://github.com/anthropics/claude-code/issues/74709) (80/90/100% alerts), [#104967](https://github.com/anthropics/claude-code/issues/104967) (limit used per request) and Codex [#5085](https://github.com/openai/codex/issues/5085).
- Audit trails: Claude Code [#33141](https://github.com/anthropics/claude-code/issues/33141) asks for an "audit" permission level. Codex [#12190](https://github.com/openai/codex/issues/12190) asks for governance hooks with JSONL audit for SOX/SOC2. In [discussion #27766](https://github.com/openai/codex/discussions/27766), the poster says "a billing summary is not an audit trail".
- Destructive actions: `rm -rf ~/`, the 48k-file deletion and production database wipes ([cybersecuritynews](https://cybersecuritynews.com/claude-code-agent-file-deletion/), [chatforest](https://chatforest.com/builders-log/ai-agents-deleting-home-directories-rm-rf-gpt56sol-claude-cli-tilde-expansion-sandbox-builder-guide/)). A common thread is that sandboxing was off.
- Endpoint noise: Sophos found that agents trigger EDR rules and advises keying those rules on the agent's process tree ([THN](https://thehackernews.com/2026/07/ai-coding-agents-found-triggering.html)).
- Skills supply chain: in the ToxicSkills audit, 13.4% of skills had critical issues and 76 carried payloads. Scanners were bypassed through later updates to skills ([CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-agent-skill-scanner-bypass-20260629-csa/)).

## 3. Ranked candidate features

**1. Budget enforcement, not just alerts. TOP 5**
- Problem: interactive sessions can't be capped, and loops burn money overnight. Evidence: #95964, #74709, Codex #5085.
- Who has it: Guardian Runtime (proxy), Bifrost (gateway). Claude Code only in `-p` mode.
- Fit: high. `--budget` alerts, cost and block projection already exist. Add caps per session, per 5-hour block and per day to the coach PreToolUse hook (ask, or deny), with 80/100% thresholds. It's local and needs no proxy.
- Effort: S-M.
- Risks: cost is estimated at list price, so subscription users need a "block %" mode instead. A cap that is too low blocks real work, so default to ask, not deny.

**2. Guard, coach and alerts for other agents' hooks. TOP 5**
- Problem: guard and loop breaker cover only Claude Code. Codex, Cursor, Gemini CLI and Copilot CLI now have pre-tool hooks ([Pillar](https://www.pillar.security/blog/best-ai-coding-agent-security-tools-for-the-enterprise-2026); Codex hooks.json, which `config-scan` already reads).
- Who has it: Belay (11 agents, AGPL/commercial), Pillar, Nightfall.
- Fit: high. `guard.py` uses only the standard library and is independent of any agent. Add an adapter per agent for the hook's JSON in and out, and an `agentwatch hooks install --agent codex` helper that prints the config rather than editing it silently.
- Effort: M.
- Risks: hook schemas change often, and each agent needs a live check. Keep the hooks fail-open and fast.

**3. Sandbox and permission posture per running agent. TOP 5**
- Problem: most deletion incidents happened with sandboxing off or approvals skipped. Users can't see at a glance which live agents are running with `--dangerously-skip-permissions`, Codex `--yolo` / `danger-full-access`, or outside srt, a devcontainer or a container.
- Who has it: Pillar (enterprise config posture). No local open-source tool shows it for live processes.
- Fit: very high. `ps` and discovery already read the process command line, parents and cwd. Add a POSTURE column (sandboxed / approvals on / yolo) to `ps` and `watch-all`, and a `check` warning. Detect srt, bwrap, sandbox-exec, docker and devcontainer from the parent chain.
- Effort: S.
- Risks: telling a sandbox from a plain container is guesswork, so label confidence. The process command line can hold secrets, so show only flags.

**4. Skill, plugin and MCP drift pinning in `config-scan`. TOP 5**
- Problem: skills turn malicious after an update, and attackers rug-pull MCP configs. Today config-scan reads only skill markdown, not the scripts in a skill.
- Who has it: Snyk Agent Scan (needs a token and network), SkillMD scanner.
- Fit: high, and it stays offline. Hash each skill dir, plugin installPath and MCP server entry into data_dir (`config-scan --baseline`), then report anything added or changed since. Scan scripts inside skills for curl|sh, base64-decode-exec, reads of credential paths and obfuscated downloads using the existing patterns.
- Effort: M.
- Risks: false positives in legitimate install scripts, which call for an allowlist per hash. It can't see tool descriptions served at runtime without starting servers, and it shouldn't start them.

**5. Session audit ledger and "blast radius" report. TOP 5**
- Problem: compliance teams and people who just had files deleted both want to know what the agent ran, which files it changed or deleted, and which were outside the repo. Evidence: #33141, Codex #12190 and #27766, the deletion incidents.
- Who has it: Codex Compliance Export (Enterprise only), Cage monitor mode. Nobody offers it locally across agents.
- Fit: very high. Actions are already normalised for 12 agents. Add `agentwatch ledger [--log] --format jsonl|csv` with commands, file writes and deletes, out-of-project paths, network hosts and guard decisions, redacted through `one_line`, plus a summary of destructive actions in `check`. Schema-versioned, so it can feed SIEMs.
- Effort: M.
- Risks: privacy, since commands and paths are sensitive, so redact by default. Ledger files are large.

6. **OTLP export of agentwatch metrics and findings.** Teams already run Grafana, CloudWatch or Datadog dashboards on agent OTel data, and agentwatch findings (loops, test tampering, injection) would add something those dashboards lack. Fit: opt-in, with no server of its own, like the `siem` extra. Effort M. Risks: the OTel dependency's weight, and data leaving the machine because a user configured it to.
7. **Local AI-attribution report.** Correlate Edit/Write actions with `git log` to show the AI share for each commit or branch (git-ai, Claude Code and Cursor analytics have this, but only on paid plans). Read-only git. Effort M-L. Risk: the attribution is approximate.
8. **Real quota view.** Show the share of the 5-hour and weekly limits each session used, using tokens the logs already record, calibrated to plan type ([#104967](https://github.com/anthropics/claude-code/issues/104967)). Reading the OAuth limit endpoint would break the no-network rule, so make it opt-in. Effort S-M.
9. **Context % and git branch per session in `watch-all` and `ps`.** agenthud and futin have this. Effort S. Low risk.
10. **Self-contained HTML session report.** A transcript timeline with findings shown inline, from `visual`. Many replay tools exist, but none overlays health and security findings. Effort M. Risk: secrets in the export, so redact.
11. **Scheduled digest.** A daily or weekly `report` sent through the existing webhook or desktop alert, with no LLM. Effort S.
12. **Process-tree export for EDR tuning.** Output the processes that agents spawned (pid, parent chain, command flags) so Sophos-style rules can be scoped. Effort S-M. Risk: the command line can contain secrets.
13. **Opt-in LLM pre-call judge** in the coach hook, in the style of CHATS-lab, reusing the `llm` extra. Effort M. Risks: latency and cost on every call, and data sent to the LLM.

Out of scope for the design: answering prompts from a phone (it writes to the agent), proxies that block network egress, and enforcement sandboxes. Recommend srt or devcontainers, and report posture (item 3) instead.

**Why these top 5:** each one answers a documented complaint, reuses code that already exists (`--budget`, guard.py, process discovery, config-scan, the 12 normalised parsers) and stays local and read-only, apart from hooks the user opts into. Items 1, 2 and 3 are cheap and help single developers right away. Items 4 and 5 are what security and compliance teams will ask for before they adopt it.

## 4. Positioning: what agentwatch has that others lack

- **Health judgement, not just telemetry.** Loop, thrash, stall, error-spiral, context-rot and test-tampering detectors give a score. Others show tokens and traces but not "your agent is stuck".
- **Wide local coverage across agents for both health and security:** 12 agents, including Cline, Kilo, Copilot for VS Code, Cowork and the ChatGPT Codex view. Security vendors are enterprise products, and local monitors mostly cover Claude Code and Codex.
- **Agent-facing intervention.** The coach hook tells the agent why it is stuck, and the loop breaker stops a repeating call. I found no competitor that feeds health findings back into the agent.
- **Free, deterministic, no account.** Snyk needs a token, the enterprise tools are sold by quote, and Langfuse and LangSmith send traces to a cloud.
- **Machine-wide view.** `detect` and `net` show AI use and per-agent network endpoints, which only EDR and enterprise products offer.
- **CI exit codes** for health and security in one tool.
