# agentwatch-main -- Project Context

> Generated by loom v1.7.6

## What This Is
AgentWatch (package name `agentwatch-monitor`) is a real-time health and
security monitor for AI coding agents (Claude Code, Moltbot today; Cursor,
Aider, and Codex CLI planned). It watches an agent's session logs as they
stream, detects problems like loops, thrashing, context rot, error spirals,
credential leaks, prompt injection, and data exfiltration, and surfaces the
result as a CLI report, a CI-friendly exit code, or a live Textual TUI. Built
for developers and teams running autonomous/semi-autonomous coding agents who
want a "fitness tracker + security guard" for those agents.

**Repo:** agentwatch-main

## Stack
- **Language:** Python >=3.11 (targets 3.11 and 3.12)
- **Package/build:** `hatchling` build backend, distributed as `agentwatch-monitor` (PyPI)
- **CLI framework:** Click (`click>=8.0.0`) — not Typer/argparse
- **TUI framework:** Textual (`textual>=0.50.0`)
- **File watching:** `watchfiles>=0.21.0` (async, used for tailing agent log files)
- **Data modeling:** Pydantic (`pydantic>=2.0.0`)
- **Testing:** pytest + pytest-asyncio (`asyncio_mode = "auto"`), tests live in `tests/`
- **Linting:** Ruff (`pyproject.toml` `[tool.ruff]`: line-length 100, target py311, rules E/F/I/N/W)
- **Optional extras:** `llm` (anthropic, ollama — opt-in Tier-2 LLM analysis), `siem` (python-json-logger)
- **Hosting/Distribution:** published to PyPI via GitHub Actions on release (no server component — this is a CLI tool, not a hosted service)

## Architecture
```
src/agentwatch/
  cli.py              Click command group: check, watch, watch-all, ps,
                       list-detectors, security-scan, themes, stats, audit.
                       Entry points: `agentwatch` and `agentguard`
                       (security-first alias), both -> agentwatch.cli
  __init__.py          Public package API re-exporting detectors/health/parser/etc.
  discovery.py         Finds running agent OS processes via regex process
                       matching; builds process/team trees (PPID chains)
  cc_stats.py          Parses ~/.claude/projects/*.jsonl for token-usage /
                       burn-rate stats
  themes.py             Pluggable status-label/emoji/color themes shared by
                       CLI, health scoring, and the TUI

  parser/
    models.py           Action / ActionBuffer / SessionStats / ToolType /
                       MetricResult data models
    logs.py              JSONL parsers per agent log format (Claude Code,
                       Moltbot), sensitive-path pattern matching
    watcher.py           LogWatcher (single file, tail + watchfiles) and
                       MultiLogWatcher (multi-file, process/team-aware)

  detectors/
    base.py              Detector / SecurityDetector ABCs, Category,
                       Severity, Warning dataclass
    registry.py          DetectorRegistry; create_registry(mode=
                       "health"|"security"|"all") auto-collects detectors
    health/*.py          Health detectors: loops, tool_thrash, stall/stuck,
                       errors, context, repetition, behavioral, progress,
                       constraints
    security/*.py        Security detectors: credentials, injection,
                       network, privilege, supply_chain, secret_scanner

  health/
    score.py             calculate_health / calculate_efficiency /
                       calculate_team_health / calculate_security_score
    rot.py               RotScorer — EMA-smoothed "context rot" composite
                       metric + state machine

  ui/
    app.py               Single-agent Textual App (HealthBar,
                       SecurityStatus, EfficiencyBar widgets)
    multi_app.py          Multi-agent Textual App (MultiLogWatcher + team
                       health aggregation)
    rot_widget.py         ContextHealthWidget for rot visualization
```

## Key Patterns
- **Detector plugin pattern:** every check subclasses `Detector` /
  `SecurityDetector` (`detectors/base.py`) implementing
  `check(buffer) -> Warning | None`. `DetectorRegistry` /
  `create_registry()` (`detectors/registry.py`) auto-collects detectors and
  exception-isolates each one so a single detector failure never crashes a
  scan.
- **Streaming log parser + watcher:** `parser/logs.py` normalizes
  agent-specific JSONL formats into a unified `Action` model.
  `parser/watcher.py`'s `LogWatcher` tails files by byte offset via
  `watchfiles.awatch`; `MultiLogWatcher` layers on process-based discovery
  (`discovery.py`) to watch only live agents' logs and track team
  membership/staleness.
- **Layered scoring model:** raw `Warning`s roll up into per-category
  `CategoryScore` (weighted, e.g. PROGRESS 0.35 / ERRORS 0.30 / ...), then
  blend into an `overall_score` combining the detector score, an
  `EfficiencyReport` (resource/cost/cache penalties), and `RotScorer`'s EMA
  context-rot metric (`health/score.py`, `health/rot.py`), all tunable via
  `HealthWeights`.
- **Theme-driven status vocabulary:** `themes.py` supplies status
  labels/emojis/colors consumed uniformly by the CLI (`click.style`),
  health scoring, and the Textual UI, decoupling severity thresholds from
  display text.
- **TUI as a pure consumer:** `ui/app.py` / `ui/multi_app.py` hold no
  detection logic themselves — they subscribe to `LogWatcher` /
  `MultiLogWatcher` action streams and re-render reactive widgets from
  `health/score.py` / `health/rot.py` outputs. The plain-CLI `check` /
  `security-scan` commands reuse the same scoring layer via
  `print_health_report` in `cli.py`.

## Memory

Claude Code v2.1.59+ ships native auto-memory at `~/.claude/projects/<project-slug>/memory/`. The `MEMORY.md` index is auto-injected on session start; topic files live alongside it using a `{category}_{topic}.md` naming convention (`project_*`, `feedback_*`, `user_*`, `reference_*`). Use the `/memory` slash command to view or edit. Persona files have a richer Memory section — this is the project-level summary so an arbitrary tool that reads CLAUDE.md (Cursor, Codex, etc.) sees the convention too.

## Known Issues
- This working copy's local `.git` was a fresh `git init` with no remote
  and no history — it was **not** actually disconnected from upstream
  history, though. `origin` (`https://github.com/LoomLabs-Venture-Studio/
  agentwatch`) has 30 real commits and tags through `v0.1.6`, published to
  PyPI via Trusted Publishers. Sprint 0/1 work below was done as a real
  delta on top of that history (verified via `git fetch origin` + content
  diff against `origin/main`, not assumed from the empty local `.git`), not
  as a from-scratch bootstrap. Corrected 2026-07-10 after the original
  "no git history existed" framing here turned out to be wrong.
- CI previously had no test/lint gate at all — `.github/workflows/
  verify-deploy.yml` was a generic Loom Node.js deploy-graph checker
  irrelevant to this Python package, and `publish.yml` could publish to
  PyPI without any test ever running. Fixed in Sprint 0 by repurposing
  `verify-deploy.yml` into a real install + ruff + pytest gate.
- README.md and `docs/index.md` previously disagreed on detector counts
  (17 vs "35 detectors") and which agent CLIs are actually supported
  (Cursor/Aider/Codex). Reconciled in Sprint 0 against the actual registered
  detectors in `detectors/registry.py`.
- Local dev env requires `pip install -e ".[dev]"` before `pytest` can
  collect anything — the package is not on `sys.path` by default.
- The two-tier LLM analysis (Ollama/Haiku, `llm` extra) is explicitly
  opt-in/Tier-2 per the README — treat it as less battle-tested than the
  deterministic detectors.
- **Native Windows support landed** (Task #7): `discovery.py` now uses
  `psutil.process_iter()` / `psutil.Process.cwd()` / `psutil.Process.
  open_files()` instead of shelling out to `ps`/`lsof`. Path encoding for
  Claude Code's `~/.claude/projects/<encoded>` lookup moved to a shared
  `path_encoding.py` (`encode_path_for_claude`), replacing `/`, `\`, `:`,
  and space with `-` — the Windows rule was verified empirically against a
  real `~/.claude/projects/` entry, not guessed. `psutil>=5.9.0` is now a
  core dependency. 270/270 tests pass, including the previously-failing
  `test_cc_stats.py::TestCwdMapping::test_cwd_to_project_dir_existing`.
