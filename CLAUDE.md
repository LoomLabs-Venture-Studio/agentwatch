# agentwatch-main -- Project Context

> Generated by loom v1.7.6

## What This Is
AgentWatch (package name `agentwatch-monitor`) is a real-time health and
security monitor for AI coding agents: full support for Claude Code and
Moltbot; Aider (Markdown chat-history, including live tailing) and Cursor
(SQLite composer store, process-gated discovery + live tailing) are also
wired end-to-end and live-tested against real installs; Codex CLI support
is fixture-verified only — a genuine `@openai/codex` install has now been
confirmed reachable (2026-07-15) but no live authenticated session/rollout
has been captured against it (no credentials in this environment — see
Known Issues). GitHub Copilot CLI and Antigravity CLI (`agy`) are wired
end-to-end and live-verified (Copilot 1.0.90, agy 1.2.14, 2026-10-01).
OpenCode (read-only SQLite `opencode.db`) is wired end-to-end; its parser
is built from real opencode 1.18.34 sessions (scrubbed fixture) and
matches the 2026-10-05 live research, but `ps`/`watch-all` against a
running opencode has not been live-verified (no install on the dev
machine). Kilo Code 7.x (an OpenCode fork: CLI `kilo` and the VS Code
extension's bundled `kilo serve`) reuses the OpenCode adapter/parser on
`~/.local/share/kilo/kilo.db`; fixture-verified only against
Kilo-Org/kilocode @ ff20ca7 (no install). Kilo 5.x is out of scope (board,
#118). Gemini CLI is wired end-to-end but fixture-verified only
(format checked against the gemini-cli 0.62.0/0.63.0 source; no local
Gemini session to live-test, 2026-10-07). GitHub Copilot in VS Code
(agent-mode chats, read from VS Code's `chatSessions/*.jsonl` mutation
logs) is wired end-to-end and live-verified on Windows (VS Code 1.140,
2026-10-09, #87): `ps`, the `watch-all` engine (headless) and `check`. The ChatGPT desktop app's
Codex view runs the same Codex engine and writes the same rollouts as
Codex CLI, and is live-verified on Windows (2026-10-09, #74): `ps`, the
`watch-all` engine (headless) and `check` against one real code-mode
thread. Claude Desktop (Cowork sessions)
is wired end-to-end and fixture-verified; Windows MSIX path verified against
the real file layout; app gate live-verified against 2.31226, but current
VM-mode Cowork sessions are not visible on the host (transcript inside
sessiondata.vhdx), so only host-loop sessions surface and live
`ps`/`watch-all` of a session was not achieved (see Known Issues);
non-Store Windows and macOS paths unverified; MCP logs not parsed
(redacted by the app). Cline (VS Code extension
`saoudrizwan.claude-dev`, both the legacy globalStorage store and the SDK
store `~/.cline/data/sessions/`, plus the Cline CLI) is wired end-to-end
but fixture-verified only; live testing not approved (#104). It watches an agent's session logs as they
stream, detects problems like loops, thrashing, context rot, error spirals,
credential leaks, prompt injection, and data exfiltration, and surfaces the
result as a CLI report, a CI-friendly exit code, or a live Textual TUI. Built
for developers and teams running autonomous/semi-autonomous coding agents who
want a "fitness tracker + security guard" for those agents.

**Repo:** agentwatch-main

## Stack
- **Language:** Python >=3.11 (targets 3.11 and 3.12)
- **Package/build:** `hatchling` build backend, distributed as `agentwatch-monitor` (PyPI)
- **CLI framework:** Click (`click>=8.0.0`) — not Typer/argparse
- **TUI framework:** Textual (`textual>=0.50.0`)
- **File watching:** `watchfiles>=0.21.0` (async, used for tailing agent log files)
- **Data modeling:** Pydantic (`pydantic>=2.0.0`)
- **Testing:** pytest + pytest-asyncio (`asyncio_mode = "auto"`), tests live in `tests/`
- **Linting:** Ruff (`pyproject.toml` `[tool.ruff]`: line-length 100, target py311, rules E/F/I/N/W)
- **Optional extras:** `llm` (anthropic, ollama — opt-in Tier-2 LLM analysis), `siem` (python-json-logger)
- **Hosting/Distribution:** published to PyPI via GitHub Actions on release (no server component — this is a CLI tool, not a hosted service)

## Key Patterns
- **Detector plugin pattern:** every check subclasses `Detector` /
  `SecurityDetector` (`detectors/base.py`) implementing
  `check(buffer) -> Warning | None`. `DetectorRegistry` /
  `create_registry()` (`detectors/registry.py`) auto-collects detectors and
  exception-isolates each one so a single detector failure never crashes a
  scan. Security findings persist for the whole session (`SessionScan`);
  repeat-notification dedup lives in the consumers (the UI's
  `_alerted_signals`, the SIEM exporter, `_feed_findings`).
- **Streaming log parser + watcher:** `parser/logs.py` normalizes
  agent-specific JSONL formats into a unified `Action` model.
  `parser/watcher.py`'s `LogWatcher` tails files by byte offset via
  `watchfiles.awatch`; `MultiLogWatcher` layers on process-based discovery
  (`discovery.py`) to watch only live agents' logs and track team
  membership/staleness.
- **Layered scoring model:** raw `Warning`s roll up into per-category
  `CategoryScore` (weighted, e.g. PROGRESS 0.35 / ERRORS 0.30 / ...), then
  blend into an `overall_score` combining the detector score, an
  `EfficiencyReport` (resource/cost/cache penalties), and `RotScorer`'s EMA
  context-rot metric (`health/score.py`, `health/rot.py`), all tunable via
  `HealthWeights`.
- **Theme-driven status vocabulary:** `themes.py` supplies status
  labels/emojis/colors consumed uniformly by the CLI (`click.style`),
  health scoring, and the Textual UI, decoupling severity thresholds from
  display text.
- **TUI as a pure consumer:** `ui/app.py` / `ui/multi_app.py` hold no
  detection logic themselves — they subscribe to `LogWatcher` /
  `MultiLogWatcher` action streams and re-render reactive widgets from
  `health/score.py` / `health/rot.py` outputs. The plain-CLI `check` /
  `security-scan` commands reuse the same scoring layer via
  `print_health_report` in `cli.py`.
